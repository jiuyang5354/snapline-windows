# Snapline Windows 验证记录

首次验证：2026-10-07；v1.3.0 新界面复验：2026-10-08；v1.3.1 覆盖升级复验：2026-10-10（Asia/Hong_Kong）。

## 结果

发布程序与测试程序均使用 C# 5 / 系统 .NET Framework 编译器构建，零编译警告。v1.3.0 自动检查 **110 / 110 通过**，覆盖原有存储、剪贴板、快捷键、更新与便捷功能，以及新工具条、四页设置和界面渲染。测试源码为 `qa/Tests.cs`，完整结果由 `build.ps1 -Test` 写入 `qa/output/test-results.txt`。更新测试使用隔离的 HTTP 响应；真实联网可在公开版本文件发布后单独运行 `bin/Snapline.Tests.exe --network qa/output/network`，不计入这 110 项。

执行环境为本机 Windows x64，系统版本 `10.0.26200.0`，.NET Framework 注册表 Release 值 `533509`。目标为 Windows 10 / 11 + .NET Framework 4.8 或更高；本次没有在独立 Windows 10 机器或 32 位系统上测试。

## 视觉证据

`qa/output/line-render.png` 是实际 WPF 窗口内容的透明渲染；`qa/output/preview.png` 将该窗口内容放在展示背景上。图片卡片里的内容均为代码生成的测试样本，没有使用用户截图或上游受限宣传素材。

`qa/output/settings-general.png`、`settings-keys.png`、`settings-storage.png`、`settings-about.png` 是新设置四页的实际 WPF 渲染；`hotkey-dialog.png` 包含真实录入状态。当前版本已用真实 WPF 窗口保存/取消偏好，同时确认系统开机启动项保持原值。录键验证使用原生窗口键盘消息；Ctrl / Alt / Shift / Win 的修饰位转换已验证，尚未逐一用实体键盘检查所有组合与键盘布局。

`qa/output/tray-menu.png` 和 `qa/output/update-dialog.png` 是实际 WinForms 控件渲染。更新窗口中的 v1.4.0 为生成的测试版本，供验证比较和对话框使用，不是实际发布版本。

本机匿名访问 GitHub REST Releases API 返回限流 403，公开 raw 文件与 release ZIP 均返回 200，因此更新检查读取仓库公开的 `update.json`，无需账号令牌。发布包的 SHA-256 来源与 GitHub 上传文件摘要一致；[GitHub 发布摘要说明](https://github.blog/changelog/2025-06-03-releases-now-expose-digests-for-release-assets/)。

v1.2.0 的真实 .NET HTTP 检查暴露了目标框架标识缺失造成的 HTTPS 握手失败。v1.2.1 明确标记 .NET Framework 4.8 并在程序配置中启用系统默认 TLS 与强加密，按 [Microsoft TLS 指南](https://learn.microsoft.com/en-us/dotnet/framework/network-programming/tls) 由操作系统选择协议。发布前已用同一份修正后源码实际读取公开 README（HTTP 200），并下载已发布的 v1.2.0 ZIP、完成大小与 SHA-256 校验；不修改系统 TLS 注册表、不跳过证书校验。回归检查同时验证目标框架和 SystemDefault 状态。

2026-10-08 发布 v1.2.1 及版本文件后，另外执行真实匿名联网检查 **4 / 4 通过**：公开版本文件读取、程序自身版本比较、实际 GitHub ZIP 下载与 SHA-256 校验、下载临时文件清理。记录位于 `qa/output/network-v1.2.1/network-results.txt`。GitHub 上的便携包、源码包及校验文件均已下载回本地，与发布前文件逐一比较 SHA-256 一致。便携包共 8 个文件、源码包共 27 个文件，打包时已与对应源码 / 已测试 EXE 逐文件核对。

## EXE 安装包验证

2026-10-08 追加 EXE 安装包验证：**48 / 48 安装器检查通过**。使用已发布的 v1.2.1 便携 ZIP，核对全部 8 个安装文件逐字节一致；验证当前用户权限、默认桌面快捷方式及其目标/图标/工作目录、取消创建、覆盖安装切换选项、开始菜单、带中文和空格的卸载命令、卸载保留截图/设置及非安装器文件、只清理指向本次安装的启动项。

安装器测试通过同一 NSIS 脚本的 QA 构建执行真实安装与卸载，快捷方式重定向到 `qa/output/installer/`，登记与启动项测试使用 `HKCU\Software\Snapline-InstallerTests`，完成后清理。真实桌面、真实应用列表和用户启动项未被修改。生产安装包的 `asInvoker` 清单与排除 QA 路径已经核对。原有 91 项程序检查为此前验证记录，本次没有重新运行会操作剪贴板的程序测试。

可通过 `package-installer.ps1 -Test` 复现，完整结果见安装器源码 ZIP 中 `windows/qa/installer-results.json`。真实 Windows 应用列表显示、OneDrive 等桌面重定向及用户点击启动/卸载仍需安装验收。

## v1.3.1 覆盖升级验证

2026-10-10 程序回归 **110 / 110 通过**，安装器检查 **74 / 74 通过**。复现了旧安装器忽略已登记的自定义目录的问题，修复后不指定 `/D` 即沿用旧目录。回归使用已公开且 SHA-256 固定的 v1.3.0 便携包作为旧程序样本，启动同一安装位置的两个独立数据目录实例，并同时运行另一目录的便携副本。

升级前对照旧 EXE 版本及摘要，升级后确认两个旧实例的退出码均为 0，原位置 EXE 与已验证新版完全一致，应用登记更新为 1.3.1，只有一个桌面图标。截图、设置、桌面和开始菜单快捷方式逐字节保持原样，快捷方式中的 `--data-dir` 参数和已启用的启动命令保留；另一目录的进程与 EXE 均不变，无关文件保留。安装器仍在私有 QA 目录与注册表运行，不修改真实桌面、应用登记或启动设置。

本机默认快捷键已被其他程序占用，程序回归改用已有测试辅助方法选出的空闲组合，仍验证真实 `RegisterHotKey`、消息触发、冲突与回滚；未修改用户绑定。安装器通过查询完整 EXE 路径限定退出对象，结束其 WPF GUI 消息循环，不按进程名批量终止。复现命令和报告分别为 `package-installer.ps1 -Test` 与 `qa/output/installer/installer-results.json`。

## 尚需人工检查的范围

下列功能已经实现，但本次没有声称完成端到端人工验证：

1. 在不同缩放比例的多个物理显示器之间，从屏幕顶部展开。
2. 用真实鼠标执行单击、双击、长按和拖动的完整手势。
3. 具体聊天软件、设计工具和资源管理器的实际拖放接收效果。目标应用决定接收图片还是文件，以及复制还是移动。
4. 默认图片查看器与画图的打开、编辑体验；保存文件触发缩略图刷新的底层监听已自动验证。
5. 实际全屏游戏、视频与 F11 浏览器的收起行为；判定逻辑已通过真实窗口几何测试。
6. 各种实体键盘布局、Win 组合及设备专有按键的录入体验；系统保留或设备未提供普通按键事件的键无法保证可绑定。
7. Windows 登录 / 重启后实际启动、Windows 启动项禁用状态与安全软件拦截。
8. Windows 系统通知的实际点击行为、浏览器与资源管理器关联程序、不同网络代理；当前便携更新需手动退出、解压和启动。

建议快速验收：启动程序，按 Win+Shift+S 截图；靠近屏幕顶端；单击后在画图粘贴；双击预览；长按进入画图，保存后检查缩略图；把图片拖入目标应用和一个测试文件夹；最后从托盘退出。
